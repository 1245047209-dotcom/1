## Beats 主动查询及旧读数清除（build v53）

- 原版 Beats Studio Buds 改用官方 Android App 使用的 B2P 串口电量查询。连接已配对地址的标准 SPP 服务，只发送型号查询 0x013A 和部件状态查询 0x0430。
- 型号回复必须为已实测的 0x2011；查询包和回复验证 CRC、长度、序号、响应命令与状态，防止把旧请求或其他协议的回复当成新数据。
- 原生回复以 02 / 04 / 08 标识右耳、左耳、充电仓。状态 04 表示不可读取；其中的零是占位值，不显示为 0%，也不继续保留 Fast Pair 的旧仓电量。
- 已实测读取到充电仓 99%、正在充电，与手机显示一致；同时读到右耳 88%、充电中，左耳 100%、充电完成。满电时状态 00 按官方 getter 的规则处理，避免把整包误判为异常。
- 每 5 秒主动查询，点击刷新会唤醒查询；断线、错误或超过 12 秒未取得新回复时清除独立读数。
- 本机旧 Fast Pair 通道长时间给出仓 44%，与用户手机的 59% / 99% 不一致；该通道不能据此承诺仓电量实时。新通道若仍将仓标为不可读取，界面会明确显示 --。
- 协议字段参考：[PairFree B2P 协议记录](https://github.com/Omega-Destroyer/PairFree/blob/main/docs/apple/B2P.md)，并用官方 Beats 2.12 库及本机设备响应交叉核对。未使用其中的设置、重置、固件或密钥命令。

## Beats Studio Buds 三路独立电量（build v48）

- 使用 Google 官方 Fast Pair Message Stream，通过已配对的蓝牙地址连接 RFCOMM 服务 `df21fe2c-2515-4fdb-8886-f12c4d67927c`，监听 `0x03 / 0x03` 电池通知。
- 三个字节依次表示左耳、右耳、充电仓；每字节高位为充电标志，低 7 位是 0～100 的电量，127 表示未知。未知显示“--”，不当作 0，也不把 Windows 的整体电量复制到各电池。

- 充电仓读数可能由耳机转报最近一次获知的仓电量；需要开盖或耳机入仓才能刷新，合盖休眠后不保证持续实时更新。界面明确提示“仓电量开盖后更新”。
- 总览及单设备视图分别列出三路电量与充电图标，保留固定窗口、右下角打开位置和非线性过渡。
- 官方依据：[Beats Studio Buds 支持 Google Fast Pair](https://www.beatsbydre.com/support/earbuds/studio-buds)、[Google 电池通知格式](https://developers.google.com/nearby/fast-pair/specifications/extensions/batterynotification)、[变化通知与 Message Stream](https://developers.google.com/nearby/fast-pair/specifications/extensions/deviceinformation)。

## 鼠标实时监测（build v42）

- 面板打开时，为已加入的 PRO WIRELESS 保持独立的共享 HID 连接，监听 `0x1001` 电池电压广播；收到变化后在下一次界面检查中更新（最多约 1 秒）。
- 同时每 5 秒主动核对一次电压和充电状态，防止没有广播时长时间不更新；无需等待其他设备的 30 秒刷新。
- 百分比从旧版的 5% 取整改为 1% 分辨率，使用 Linux HID++ 的 100 点公开电压曲线。例如 `3978 mV` 显示“约 78%”，不会再取整为 80%。
- **实时更新不等于精确测量。** 此型号已验证的原生电池接口提供电压；曲线估算会受电池特性影响。1% 分辨率不表示 1% 测量精度，仍保留“约”字和实测电压，不保证始终与 G HUB 相同。
- 断连、查询错误或超过 12 秒未更新的数据不会冒充当前电量；重新发现接收器后自动恢复。仅监听所选物理接收器，忽略其他客户端的请求回复。
- 关闭面板或移除设备时停止对应监听并关闭 HID 句柄；不改变驱动、DPI、灯光或配对，不写入 G HUB 设置，也不依赖 G HUB 进程。
- 保留三设备同屏和单设备排版；键盘及蓝牙设备沿用各自的刷新与读取逻辑。
- 依据：[Linux HID++ 的电池事件及电压曲线](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-logitech-hidpp.c)、[LGSTrayBattery 的 0x1001 读取实现](https://github.com/andyvorld/LGSTrayBattery/blob/master/LGSTrayHID/Features/Battery1001.cs)。

## PRO WIRELESS 协议直读（build v41）

- 电量读取固定使用鼠标自身的 HID++ 2.0 `0x1001` Battery Voltage 接口，不访问 G HUB 本机 IPC、推送缓存或数据库。
- 查询所选物理接收器的 `FF00 / Usage 2` 长报文接口（Report ID `0x11`，20 字节，Device Index `1`），通过 IRoot `GetFeature(0x1001)` 动态获取功能索引，不能把索引写死。
- 本机确认型号为 `G Pro Wireless Gaming Mouse`，接收器 `046D:C539`；实测 `0x1001` 索引为 `6`，回复 `0F 96 00` 表示 `3990 mV`、电池供电。
- 实测该鼠标未提供 `0x1000`、`0x1004` 电量百分比功能，也未提供 `0x1F20`。它直接报告的是电压；百分比使用电压曲线，显示“约 X%”并显示实测电压。v41 的 5% 取整已在 v42 改为 1% 分辨率。
- 使用当前设置的刷新间隔和手动刷新；单次查询超时会换用新的事务 ID 重试一次，忽略上一事务的迟到回复。两次均无响应或断连时清空本次电量，不回退到旧 G HUB 数值。鼠标休眠时可移动鼠标唤醒后刷新。
- 不再显示 G HUB 估计的剩余时长；鼠标暂显示“暂不支持估算”。保留键盘自身的续航估算和蓝牙设备读取。
- 查询使用共享 HID 句柄，只发送型号和电池状态读取命令，不修改 DPI、灯光、配对或配置文件。
- 官方协议入口：[Logitech HID++ 2.0](https://github.com/Logitech/cpg-docs/blob/master/hidpp20/README.rst)、[IRoot / GetFeature](https://github.com/Logitech/cpg-docs/blob/master/hidpp20/features/0x0000-IRoot.rst)。电压及充电标志交叉核对：[Linux HID++ 驱动 0x1001](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-logitech-hidpp.c)、[Solaar 电压解析](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/hidpp20.py)。

- 未配对设备请先在 Windows 蓝牙设置中配对。程序不执行配对、不改变蓝牙或安全设置；不安装第三方依赖。
- 蓝牙电量按面板刷新间隔更新，手动刷新会读取一份新的 Windows 状态；一次刷新中多台蓝牙设备共享同一份查询结果。
- 仅有电量百分比时不推断充电状态，也不套用狼蛛续航模型；蓝牙设备暂不增加后台托盘提醒。

## 全部设备与单个设备视图（build v37）

- 默认打开“全部设备”，键盘与鼠标并排显示，各自显示电量、供电与连接状态。
- 总览中的狼蛛键盘产品图竖向展示，罗技鼠标使用对应产品图；点击卡片进入单设备详情。
- 点击顶部“单个设备”保留原有左右分区布局；键盘在单设备视图中仍横向展示。
- 两种视图都提供搜索与刷新；刷新会并行读取全部已加入设备，一台设备断连不会覆盖另一台的读数。
- 视图偏好会随已加入设备保存在 added_devices.json。加入设备、切换设备后不会重置视图偏好。
- 三台设备同屏显示；超过三台时，总览支持向下滚动查看其余卡片。
- 鼠标产品图片来源：[Logitech G PRO Wireless 官方产品页](https://www.logitechg.com/en-us/shop/p/pro-wireless-mouse)。

## 使用

- 双击桌面的“我的设备电量.bat”打开面板。
- 托盘程序会在登录 Windows 时自动启动；也可以双击“电量托盘.bat”启动。
- 托盘图标左键立即刷新，右键打开面板。
- 面板和托盘默认每 60 秒刷新，可在面板中修改。

## 设备与协议

- 设备：狼蛛 AULA F87 Pro 2.4G 接收器
- VID:PID：`3554:FA09`
- HID 接口：`0xFF02:0x0002`，20 字节输入/输出
- 查询：Report `0x13`，命令 `0x4A`
- 仅支持 2.4G 接收器模式；有线和蓝牙模式不在此部署版范围内。

键盘充电时，接收器可能只返回充电状态，界面会显示“充电中”。

## 预计剩余使用时长

- 预计的是剩余可使用时长：使用和闲置分别校准，闲置时间不当作连续使用时间，实际待机耗电仍单独计入。
- 单独识别狼蛛 `3554:FA09` 键盘的活动；鼠标、其它键盘和软件模拟按键不计入。连续 60 秒没有该键盘活动后视为闲置。只统计活动时间，不读取或记录按键内容。
- 界面每秒更新使用/闲置状态与时间推算，电量仍按设置的间隔从硬件读取。数值使用约数，避免显示不可靠的秒级精度。
- 面板和托盘共用一个活动采集器，关闭面板后托盘仍可积累数据。记录保存在本机 `battery_usage.json` 和 `battery_activity.json`，不上传数据。
- 首次显示“正在估算…”。首个电量下降建立起点，之后至少记录 2% 的有效下降、累计 15 分钟，并积累足以辨别使用耗电的活动数据后才显示约数。只有闲置记录时不会臆测连续使用续航。
- 使用最近 7 天内最多 12 个完整耗电区间；忽略充电、没有连续活动计时支持的长采样间断、单次超过 5% 的跳变及小于 1 分钟的异常下降区间。睡眠或采集器切换会切断无法可靠计时的区间；活动采集器持续运行期间的长时间闲置可用于学习待机耗电。
- 旧版耗电记录会保留；使用/闲置分类从更新后开始学习。新的实际电量会校正实时推算，推算不会越过尚未由硬件确认的 1% 电量区间。
- 充电时暂停估算，离线时不显示剩余时长。结果会随灯光、使用习惯和实际耗电速度变化，不代表厂商标称续航。

## 低电量系统通知

- 默认开启：有效电量低于 10%（0～9%）且未充电时发送 Windows 系统通知；10% 不触发。
- 面板与后台托盘共享提醒记录，同一轮低电量只提醒一次，重启后保留。
- 检测到充电，或电量恢复至 15% 以上后，才允许下一轮提醒，避免 9% / 10% 波动导致重复通知。
- 断连、读取失败及未知电量不会触发提醒。关闭面板后，只要托盘仍在运行就会继续预警。
- 在“设置”中可关闭提醒，也可点击“测试通知”预览；演示不改变真实提醒记录。
- 通知由后台托盘发送，点击通知会打开电量面板。显示方式和声音遵循 Windows 通知及免打扰设置；发送过程不会弹出确认对话框。

## 搜索其他 2.4G 接收器（build v34）

- 点击面板顶部“搜索接收器”，查看已插入电脑的无线接收器和系统报告的外设型号。
- 列表提供厂商、VID:PID 硬件 ID 和接口类型；选中设备可查看识别依据，并复制设备信息。
- 点击“重新搜索”或按 F5，更新插拔后的设备列表。搜索在后台运行，不阻塞面板。
- 同一接收器的多个 HID 接口合并显示；相同型号的两只接收器分别显示。
- 通用接收器可能不报告配对外设的具体型号。可勾选“显示无线类型待确认的 USB 外设”查看其他候选设备。
- 搜索只读取 Windows 设备信息，不执行配对或修改接收器设置；虚拟输入设备、内置触控板和蓝牙设备不列为 USB 接收器。
- 识别到型号不代表已支持该型号的电量协议，未适配的型号会明确显示状态。
## 加入设备与设备切换（build v35）

- “搜索接收器”→选中外设→“加入设备”，即可把设备保存到主面板。
- 在主面板“我的设备”中切换查看；重复加入同一接收器只会切换到已有设备。
- 已加入设备与上次选择保存在程序目录 added_devices.json，重启后保留。
- 点击“移除设备”从列表移除新增设备；默认狼蛛设备保留。移除不会卸载驱动或取消硬件配对。
- 新增设备显示本机系统报告的型号、厂商、硬件 ID 和接收器连接状态，使用通用 USB 图标。
- 尚未适配电量协议的型号会显示“待适配电量”；已适配型号使用对应的设备协议。
- 默认狼蛛设备继续使用原有电量、耗电估算、后台托盘与提醒。新增型号不参与狼蛛的耗电记录或低电量通知。
- 接收器按 Windows 设备实例识别；无序列号的接收器改插其他 USB 口后，可能需要重新搜索并加入。

## 罗技 PRO WIRELESS 电量（build v36）

- 适配本机 `046D:C539` 接收器，查询鼠标自身确认型号为 G Pro Wireless Gaming Mouse。
- 读取 HID++ 2.0 `0x1001` 电池电压及供电状态；使用大端解析，并正确区分功能索引与版本号。
- 该鼠标通过此接口报告的是电压，百分比使用电压曲线换算并显示“约 X%”。界面同时显示实测电压，可能与 G HUB 的平滑估计有差异；v42 已将显示分辨率从 5% 提高到 1%。
- 曲线仅用于已确认的 PRO WIRELESS 型号；其他型号不会自动套用相同曲线。
- 显示电池供电、充电中和已充满状态。鼠标休眠或无响应时提示唤醒重试，不把超时当成 0%，也不保留旧百分比冒充当前读数。
- 每次查询匹配设备、功能、函数及软件事务标识，避免混入广播或其他软件的回复；仅访问当前所选接收器的接口。
- 只发送型号与电池状态读取命令，不修改配对、DPI、灯光或板载设置。
- 狼蛛的续航估算、后台托盘和低电量通知继续使用原有逻辑；罗技电压后端不自行估算剩余时长，暂不增加鼠标后台提醒。
- 协议参考：[Logitech IRoot](https://github.com/Logitech/cpg-docs/blob/master/hidpp20/features/0x0000-IRoot.rst)；电压与校准数据参考：[Solaar](https://github.com/pwr-Solaar/Solaar/blob/master/lib/logitech_receiver/hidpp20.py)。

## 三设备同屏总览（build v40）

- “全部设备”在一行显示键盘、鼠标、耳机三张卡片，无需向下滚动；默认窗口 1280×700，最小 1120×650。
- 键盘在总览中保持竖放，鼠标及蓝牙设备分别显示自身卡片、电量、连接方式和剩余时长。
- 三台设备时隐藏滚动条，并固定到总览顶部；卡片内的长标题和底部说明按可用宽度省略，避免相互遮挡。
- 点击任一卡片或顶部“单个设备”，仍使用原有单设备排版；点击“全部设备”返回三台同屏。
